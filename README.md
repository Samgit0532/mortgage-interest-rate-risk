# Interest Rate Risk Hedging for Mortgage Loans

This repository contains the simulation framework developed for a second-year internship project at ENSAE, carried out within the Asset and Liability Management (ALM) team at Belfius. The study compares the margins generated by fixed-rate and periodically adjustable-rate mortgage loans, taking into account their funding costs and interest rate hedging strategies.

The objective is not to forecast interest rates or reproduce the bank's production models. Instead, the simulations provide a simplified setting in which different loan products and hedging rules can be evaluated under common interest rate scenarios.

## Methodology

Interest rate paths are generated using a one-factor Hull–White model, starting from three illustrative initial yield curves (upward-sloping, flat and downward-sloping). The model parameters are varied across experiments rather than calibrated to market data.

The framework includes:

- Monthly loan cash flows with linear principal amortisation.
- Loan pricing based on an internal transfer price (ITP) and specified margins.
- Behavioural prepayment and refinancing for fixed-rate loans.
- Interest rate swaps and monthly hedging adjustments targeting a zero net basis point value (BPV).
- Three-year rate resets for adjustable-rate loans (3/3/3).
- A protected adjustable-rate loan, with payer swaptions used to hedge the interest rate cap.

Six configurations are compared on the same simulated paths:

| Loan | Hedging strategy |
| --- | --- |
| Fixed rate | Swaps maturing at the contractual loan maturity; close outstanding swaps upon prepayment |
| Fixed rate | Swaps maturing at the contractual loan maturity; retain outstanding swaps upon prepayment |
| Fixed rate | Swaps maturing at the expected loan termination date; close outstanding swaps upon prepayment |
| Fixed rate | Swaps maturing at the expected loan termination date; retain outstanding swaps upon prepayment |
| Adjustable rate | Three-year resets, without interest rate protection |
| Protected adjustable rate | Three-year resets, capped reference rate and payer swaptions |

The comparison focuses on realised monthly and cumulative margins, downside outcomes and the size of hedging positions. A near-zero BPV at rebalancing dates does not imply a constant margin or eliminate other sources of risk.

## Installation

The project uses Python 3.12 and a Conda environment. From the repository root, run:

```bash
bash setup_env.sh
```

The script creates or updates the `fixed_variable_loans_project` environment, installs a Jupyter kernel and creates a local `.env` file with default prepayment parameters if one does not already exist. An existing `.env` is left unchanged.

For subsequent terminal sessions, activate the environment with:

```bash
conda activate fixed_variable_loans_project
```

The main dependencies are defined in `environment.yml`. No historical interest rate dataset is required: the initial curves are specified in the configuration.

## Running the simulations

To run a single experiment before starting the full batch:

```bash
python run.py --limit 1
```

To run the remaining experiments:

```bash
python run.py
```

Completed experiments are saved progressively and can be reused when restarting the batch. To regenerate CSV exports from the saved database without rerunning the simulations:

```bash
python run.py --export
```

The default output directory is `resultats/`. Avoid running multiple batches concurrently against the same output database.

For an illustration of a single simulated path:

```bash
python plot.py --seed 1
```

For other available arguments, run `python run.py --help` or `python plot.py --help`.

## Experimental settings

The principal settings are defined in `config.py`; the prepayment parameters are loaded from `.env`.

| Parameter | Default setting |
| --- | --- |
| Initial simulation date | January 2025 |
| Initial loan principal | EUR 100,000 |
| Loan maturity | 15 years |
| Initial curve profiles | Upward-sloping, flat, downward-sloping |
| Hull–White mean reversion (`a`) | 0.05, 0.10, 0.30 |
| Hull–White volatility (`sigma`) | 0.003, 0.005, 0.010 |
| Central paths per parameter combination | 50 |
| Conditional paths at each valuation date | 300 |
| Hedging frequency | Monthly |

This gives 27 combinations of curve profile and Hull–White parameters, with 50 central paths each. All six configurations are evaluated using common paths within each experiment. The resulting 1,350 experiments correspond to 8,100 loan-and-hedge evaluations.

These values are modelling assumptions, not calibrated market estimates. The configuration can be adjusted for smaller exploratory runs or additional sensitivity analyses.

## Outputs and interpretation

The simulation batch stores its results in `resultats/`, including a SQLite database and CSV exports. The main exports include monthly margins (`marges.csv`), per-experiment summaries (`resume.csv`), experiment metadata (`experiences.csv`) and instrument-level records (`swaps.csv` and `swaptions.csv`).

Monthly margin is defined as loan interest income less funding and liquidity costs, plus net swap cash flows, signed swap close-out payments and any prepayment compensation. For the protected loan, the initial swaption premium is included in the cumulative cash-flow result. Principal repayments are not treated as profit, and unrealised mark-to-market changes are excluded from the realised margin measure.

Results should be compared within the same initial curve, Hull–White parameters, maturity and simulation assumptions. In particular, comparisons between fixed-rate and adjustable-rate products also reflect differences in prepayment assumptions and pricing; they cannot be interpreted as the isolated effect of the hedging rule.

## Limitations

The framework is intentionally simplified. It uses illustrative initial curves and Hull–White parameters, a single-curve setup and stylised borrower behaviour. Transaction costs, collateral requirements and operational constraints on hedging notionals are not included. The simulated outcomes therefore illustrate the mechanisms studied in the internship report rather than provide estimates of real-world bank profitability or loss probabilities.
